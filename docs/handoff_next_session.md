# رسالة تسليم لجلسة جديدة — مشروع أذكاري (إصلاح الشاشة البيضاء)

> انسخ ما بين الخطين وألصقه كأول رسالة في المحادثة الجديدة.

## 1) السياق
مشروع Flutter اسمه **أذكاري** (`com.flc.azkari`، النسخة `1.1.0+2`) في مستودع
`ahmfalcon00868-maker/azkari-app`. المطلوب الأساسي: **تطبيق يفتح بمحتوى، ويعمل بلا إنترنت،
على Android 7 (API 24) حتى Android 16 (API 36)، بلا شاشة بيضاء وبلا خروج مفاجئ**.

الشغل السابق موجود في **PR #14**
(https://github.com/ahmfalcon00868-maker/azkari-app/pull/14)
على الفرع `arena/61463075-azkari-app`، آخر commit فيه `d59e85e`، وفرعه الأساسي `main`
(مأخوذ من `de5fd51`). **لم يُدمج في main ولم يُنشر أي Release.**

**أول خطوة تقنية لك:** ادمج شغل الـ PR في فرع الجلسة الحالية قبل أي تعديل، حتى لا تضيع
الإصلاحات:
```
git fetch origin arena/61463075-azkari-app
git merge origin/arena/61463075-azkari-app
```
(لا تدفع إلى `main`، ولا تفتح Release، ولا ترفع APK إلى أي متجر.)

## 2) حالة المهمة
- **المرحلة 1 (التشخيص): مكتملة.** السبب الجذري مُثبت من Logcat.
- **الإصلاح: مكتمل ومُتحقَّق منه على 10 إصدارات.**
- **المرحلة 2 (بدء مرن) لم تبدأ — وهي المطلوب التالي.**
- المرحلة 3 (تثبيت minSdk/compileSdk ومراجعة الأذونات) والمرحلة 4 (فحص وظيفي عميق)
  والمرحلة 5 (التقرير النهائي) ما زالت مفتوحة.

### السبب الجذري (لا تعده من الصفر)
```
Unable to get provider androidx.startup.InitializationProvider:
  Failed to create an instance of androidx.work.impl.WorkDatabase
  at w11.x(...) / w11.u(...)        ← أسماء R8
  at ActivityThread.installContentProviders
```
`androidx.work:work-runtime:2.7.1` تُجرّ ضمنيًا (التطبيق لا يستخدمها) وتُهيّئ قاعدة
WorkManager عبر `androidx.startup` **قبل `runApp()`**؛ فشل الإنشاء يقتل العملية قبل أول
إطار ⇒ شاشة بيضاء دائمة على كل الإصدارات.

### الإصلاح المطبَّق
إزالة `androidx.work.WorkManagerInitializer` من `androidx.startup` في المانيفست + قواعد
R8 تُبقي Room/WorkManager/Startup. الدليل الكمّي على DEX: `androidx.work` 35←356،
`androidx.room` 3←106. **لا كود في `lib/` تغيّر بسبب هذا الإصلاح.**

## 3) القيود التي يجب أن تلتزم بها حرفيًا
- أوقف كل ميزات جديدة حتى تُغلق مسألة البدء/الشاشة البيضاء.
- لا تدمج في `main`، لا تنشر Release، لا ترفع APK إلى APKPure أو أي متجر.
- لا تُفعّل التحديثات: `kUpdatesEnabled = false` يبقى كما هو.
- لا تحذف/تغيّر بيانات المستخدم، ولا تُزل النسخة السابقة.
- الترتيب إلزامي: تشخيص ← إصلاح معمارية البدء ← توافق Android ← اختبارات حقيقية ← تقرير. **بلا تخمين.**
- لا ترفع أو تخفّض `minSdk` عشوائيًا — افحص متطلب كل مكتبة أولًا.
- لا تدّعِ دعم Android 7–16 لمجرد نجاح البناء؛ النتائج الفعلية مطلوبة.
- اختبر نسخة `--release --obfuscate` الموقّعة واحتفظ برموز إزالة التعمية.

## 4) المطلوب التالي (بهذا الترتيب)
**المرحلة 2 — بدء مرن (ابدأ بها):** فشل الصوت أو الإشعارات أو المزامنة **لا يجب** أن يمنع
فتح التطبيق؛ الإنترنت/Supabase غير مطلوبين (offline-first)؛ فشل تهيئة التخزين ⇒ رسالة
مفهومة + زر «أعد المحاولة»، لا شاشة بيضاء ولا انهيار؛ فصل التهيئة الأساسية عن الاختيارية؛
لا واجهة نجاح وهمي. نقاط الخطر المعروفة في الكود:
- `lib/main.dart`: `main()` حوالي 556–583، `PlatformDispatcher.onError => true` في 561–563،
  `await` غير محمي في 574–578، و`initState` 779–810 فيه `await syncServerSubscription`.
- `lib/services/volume_button_service.dart` 41–50، `android_custom/.../MainActivity.kt`، و`test/` (95 اختبارًا).
- المقترح: `runZonedGuarded`، إزالة `onError => true`، تأجيل `JustAudioBackground.init()`
  والتوجيه والتفضيلات والإشعارات إلى ما بعد أول إطار، وتأجيل طلب `POST_NOTIFICATIONS`.

**المرحلة 3 — توافق:** تثبيت `minSdk = 24` صراحةً بعد مراجعة كل مكتبة، وأحدث
`compileSdk`/`targetSdk` مستقر، ومراجعة أذونات الخدمة الأمامية/الإشعارات/التخزين/الصوت/
مستقبِلات البثّ/الودجة/مستقبِل الإقلاع/Facebook SDK/Overlay وكل ABIs.

**المرحلة 4 — اختبار حقيقي:** المصفوفة أعلاه + فحص وظيفي (تنقّل، قرآن/أذكار/تسبيح،
صوت وإشعارات، ودجة، أذونات مرفوضة) + نسخة Debug.

**المرحلة 5 — تسليم:** تقرير بالسبب الجذري و Stack Trace حرفي، الملفات المُعدّلة ولماذا،
نتائج لكل إصدار مع تمييز **محاكي مقابل جهاز فيزيائي**، نتائج `flutter analyze`/`flutter test`،
**APK تجريبي فقط**، الحجم + SHA-256 + شهادة التوقيع، والرموز محفوظة، وطريقة استخراج Logcat.

## 5) دروس بيئة العمل (لا تُعِد اكتشافها)
- لا يمكن قراءة لوجات/أرتيفاكتات التشغيل عبر `gh`؛ اقرأ `check-runs/<id>/annotations`
  فقط، واطبع كل ما تحتاجه كتعليقات (`::notice::` واحد مجمّع في آخر الخطوة، لأن الحد ~10 تعليقات/خطوة).
- GitHub يشغّل `bash -e`: أي أمر يُعيد قيمة غير صفرية يُسقط الخطوة بلا رسالة. ضع `set +e`
  وأنهِ السكربت بـ `exit 0` (هذا بالضبط ما جعل API 31 يبدو «فاشلًا» في السابق، والعيب كان في السكربت لا التطبيق).
- `reactivecircus/android-emulator-runner` يفشل بصمت؛ الإقلاع اليدوي لـ `emulator` + `adb wait-for-device` هو الحل،
  ومطلوب `ANDROID_AVD_HOME="$HOME/.android/avd"` وإضافة `platform-tools` و`emulator` إلى PATH.
- صورة API 31 `google_apis` غير مستقرة على هذه الرانرات؛ استخدم `default`.
- لقطات `screencap` الخام على API 24/26 قد تنقص بضعة بايتات ⇒ `tool/screen_health.py` يتسامح.
- `ClassNotFoundException` من `com.android.settings` في 33/34/35 ضجيج نظام، ليس من التطبيق.

## 6) ما أطلبه منك الآن
اقرأ `docs/startup_crash_report.md` و`docs/startup_crash_diagnosis.md`، ثم:
1. أكّد أنك دمجت شغل PR #14 في فرع الجلسة.
2. اعرض خطة مختصرة **قبل** تعديلات المرحلة 2 (الملفات وما سيتغيّر في كل ملف).
3. بعد موافقتي نفّذ المرحلة 2، ثم أعد تشغيل مصفوفة المحاكيات للتأكد أن الخدمات الاختيارية
   (الصوت/الإشعارات/المزامنة) لم تعد قادرة على منع فتح التطبيق.
